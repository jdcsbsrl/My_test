# 业务组周报需求1003838自动化回归

## 执行入口

CI 使用 `modules/auto_test/tests/test_weekly_business_report_1003838.py`。全组金额核对由管理员账号在 TEST 环境执行；业务经理/组长和业务员分别使用独立测试进程、浏览器上下文执行只读权限回归。测试只读当前最新周报，金额来源按每份快照自己的周报截止日查询账单。

GitHub Actions 在每次 push、PR 和每晚北京时间 00:00 自动运行源账单对账；也可在 `workflow_dispatch` 额外手动复跑。该检查只读 TEST 数据，不更新周报或账单。源账单对账等待管理员、组长和业务员的 UI 回归结束后再运行，减少并发访问 TEST 环境。

本地执行管理员全组核对：

```powershell
$env:TEST_ENV = 'test'
$env:AUTO_TEST_AUTHORIZED = 'true'
$env:WEEKLY_REPORT_ROLE = 'admin'
pytest modules/auto_test/tests/test_weekly_business_report_1003838.py -m 'not slow'
```

本地全量源账单金额对账属于慢速只读检查：

```powershell
$env:TEST_ENV = 'test'
$env:AUTO_TEST_AUTHORIZED = 'true'
$env:WEEKLY_REPORT_ROLE = 'admin'
pytest modules/auto_test/tests/test_weekly_business_report_1003838.py::test_latest_week_admin_reports_match_source_receivable_bills -m slow
```

只核对六组时，设置 `WEEKLY_REPORT_GROUP_SCOPE=sixth`；默认值 `all` 保持 CI 全组核对：

```powershell
$env:TEST_ENV = 'test'
$env:AUTO_TEST_AUTHORIZED = 'true'
$env:WEEKLY_REPORT_ROLE = 'admin'
$env:WEEKLY_REPORT_GROUP_SCOPE = 'sixth'
pytest modules/auto_test/tests/test_weekly_business_report_1003838.py::test_latest_week_admin_reports_match_source_receivable_bills -m slow
```

工作流在每次 push、PR 和夜间定时任务自动执行同一核对；`workflow_dispatch` 的 `run_weekly_report_source_audit` 仅用于额外手动复跑。源账单接口只返回当前可查询状态，不能按历史报告生成时点还原账单；因此用例只在周报周期等于上海时区最近一个完整周时进行金额对账。如果最新周报尚未生成或接口仍只返回更早周期，测试会以 `SOURCE_AUDIT_INCOMPLETE` 跳过，避免把旧快照和当前账单误判为计算缺陷。该周期门禁不能重建账单历史版本；若最新周期对账仍有差异，仍需结合账单变更记录判断，不能只据差异断言产品计算错误。

| 多角色页面回归 | 管理员、业务经理/组长、业务员均检查正式 Tab、客户搜索控件、付款异常金额列、Ctrl+F；角色权限用对应独立凭证验证 |

| 数字搜索条件 | 慢速手动用例点击搜索后重载页面验证数字回显，并恢复原阈值 |

## 覆盖边界

当前没有发现由本次 `run_id` 创建并由生命周期管理器拥有、可安全清理的周报/客户/账单夹具，因此 CI 不对共享最新周报发送写请求。经过单独授权的慢速 TEST 回归已覆盖组长和一名业务员本人工作计划写入、重载、Ctrl+F、管理员查看及恢复；这不能替代对组内每位业务员的逐人验证。

最新周报的销量下降、上周新增和上上周新增回访三个板块没有样本时，不据空表判定筛选逻辑通过或失败。自动化会回退查找较早的六组周报；能找到历史样本时验证客户名和客户编号过滤，找不到时输出 `NO_SAMPLE` 并在报告中说明。本次三类均找到历史样本并验证通过。

付款信用日志口径按用户确认：当前周与上周信用相同，不新增日志。最新六组 DG12375 的两周周报值均为空，客户详情页“付款信用”控件存在；这一同值场景没有日志符合预期。当前无非空且相同的相邻周客户样本，因此该部分依照已确认规则和单元测试覆盖，不列为未解决业务问题。此前把本周周报值临时改成“优秀”后，周报值保存成功，但客户详情值和操作日志没有变化；这属于不同值变更链路的待验证结果，不影响同值不记日志的已确认规则。配齐比例核对发现明细接口的 `lockStockQty` 为空且 `deficitFlag` 对该样本不准确，订单级 `outStockMark` 才与用户 SQL 结果一致。用户提供的 SQL 明细确认 2026-11-02 至 2026-11-08 周报中 5 张订单有 1 张配齐，20.00% 正确。跨币种源账单已确认存在逐账汇率展示，但当前列表接口缺少部分账单的汇率字段，界面只显示两位小数，尚不足以作分币金额断言。

不要将共享数据写入用例加入普通 CI。工作计划、付款信用、数字筛选、部分客户集合保存和周报刷新写入仍属于慢速、需当前任务明确授权的 TEST 回归。
