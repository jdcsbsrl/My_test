# Test ERP 项目工作流程

## 概述

Test ERP 是一个集成了测试用例生成和自动化测试执行的完整测试管理平台，包含两个核心模块：

| 模块 | 职责 | 主要功能 |
|------|------|----------|
| `trae_test` | 测试用例生成 | 需求分析、知识库检索、测试用例自动生成 |
| `auto_test` | 自动化测试执行 | 环境配置、测试脚本执行、结果收集分析 |

## 项目架构

## 核心工作流程

### 流程总览

```
用户需求 ──► trae_test (测试用例生成) ──► auto_test (自动化测试) ──► 测试报告
     │                 │                        │                      │
     │                 ▼                        ▼                      ▼
     │            知识库检索               环境验证                结果分析
     └─────────────────┴────────────────────────┴──────────────────────┘
                          知识访问控制机制
```

### 阶段说明

| 阶段 | 模块 | 主要任务 | 输出 |
|------|------|----------|------|
| 1 | trae_test | 需求分析与解析 | 需求理解文档 |
| 2 | trae_test | 知识库检索匹配 | 相关业务规则 |
| 3 | trae_test | 测试用例生成 | 标准化测试用例 |
| 4 | auto_test | 环境配置验证 | 测试环境就绪 |
| 5 | auto_test | 测试脚本执行 | 测试执行日志 |
| 6 | auto_test | 结果收集分析 | 可视化报告 |

## 知识访问控制

### 模块访问权限

| 模块 | 可访问知识库 |
|------|--------------|
| trae_test | 业务规则/*, 测试规范/*, 导航规范/* |
| auto_test | 自动化规范/*, 测试规范/模板规则, 业务规则/销售模块 |
| knowledge_retriever | 全部知识库 |

### 访问控制目的

1. **防止信息过载**: 限制智能体仅能访问完成任务必需的知识
2. **避免无根据推测**: 基于明确的业务规则生成测试用例
3. **提高检索效率**: 缩小检索范围，加快知识定位
