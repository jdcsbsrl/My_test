# trae_test 模块工作流程

## 模块定位

`trae_test` 是测试用例自动生成模块，负责从用户需求出发，基于知识库中的业务规则和测试规范，自动生成符合标准的测试用例。

## 工作流程

### 流程架构

```
用户需求输入
      │
      ▼
┌───────────────┐
│ 需求解析阶段  │
│  理解需求内容  │
└───────┬───────┘
        │
        ▼
┌───────────────┐
│ 知识检索阶段  │
│ 匹配业务规则  │
└───────┬───────┘
        │
        ▼
┌───────────────┐
│ 流程梳理阶段  │
│ 分析业务流程  │
└───────┬───────┘
        │
        ▼
┌───────────────┐
│ 用例生成阶段  │
│ 按模板生成    │
└───────┬───────┘
        │
        ▼
┌─────────────────────────┐
│ 质量评分与优化阶段      │
│  五维度评分             │
│  自动优化低分用例       │
│  自动重生闭环（熔断）   │
└───────┬─────────────────┘
        │
        ▼
┌───────────────┐
│ 输出导出阶段  │
│ 导出Excel     │
└───────────────┘
```

### 阶段详细说明

#### 阶段1：需求接收与解析

**输入**: 用户测试需求描述（文本/文档）

**处理步骤**:
1. 解析需求文本，提取关键信息
2. 识别需求所属模块（销售/采购/产品/物流/财务等）
3. 确定测试范围和目标

**输出**: 需求分析文档

#### 阶段2：知识库检索与匹配

**输入**: 需求分析文档

**处理步骤**:
1. 根据需求模块，检索对应业务规则知识库
2. 匹配相关业务流程和字段规范
3. 收集历史测试用例参考

**可访问知识库**:
- 业务规则/*
- 测试规范/*  
- 导航规范/*

**输出**: 相关知识集合

#### 阶段3：业务流程梳理

**输入**: 相关知识集合

**处理步骤**:
1. 梳理业务流程节点
2. 识别关键业务规则
3. 分析正向/逆向流程
4. 识别异常场景和边界条件

**输出**: 业务流程分析报告

#### 阶段4：测试用例生成

**输入**: 业务流程分析报告

**处理步骤**:
1. 根据15字段模板生成测试用例
2. 应用P0/P1/P2优先级规则
3. 生成测试步骤和预期结果

**模板字段**:
| 序号 | 字段名 | 说明 |
|------|--------|------|
| 1 | 用例ID | 唯一标识 |
| 2 | 需求ID | 关联需求 |
| 3 | 模块 | 所属模块 |
| 4 | 功能点 | 测试功能 |
| 5 | 用例标题 | 简洁描述 |
| 6 | 前置条件 | 执行前提 |
| 7 | 测试数据 | 输入数据 |
| 8 | 测试步骤 | 操作步骤 |
| 9 | 预期结果 | 期望输出 |
| 10 | 实际结果 | 执行结果 |
| 11 | 优先级 | P0/P1/P2 |
| 12 | 测试类型 | 功能/接口/性能 |
| 13 | 测试环境 | test/uat |
| 14 | 测试人 | 执行者 |
| 15 | 测试日期 | 执行日期 |

**输出**: 测试用例集合

#### 阶段5：质量评分与优化（新增）

**输入**: 测试用例集合

**处理步骤**:
1. 使用 TestCaseScoreEngine 对每条用例进行五维度评分
   - 覆盖率(30%)：知识库关联的规则数量
   - 完整性(25%)：步骤和预期结果的完整度
   - 优先级(20%)：P0/P1/P2 等级映射
   - 可执行性(15%)：是否可自动化
   - 可维护性(10%)：用例名称规范度
2. 冷启动保护：执行次数 < 10 时仅用静态维度评分，触发人工审查
3. 自动优化：分数 < 60 的用例由 TestCaseOptimizer 自动补充步骤和预期结果
4. 自动重生闭环：TestCaseRegenerationLoop 循环优化，最多 3 次重生
5. 熔断保护：达到重生上限后标记为 needs_human_review 并触发告警

**关键工具**:
| 工具 | 用途 |
|------|------|
| TestCaseScoreEngine | 五维度评分 + 冷启动保护 |
| TestCaseOptimizer | 自动优化步骤/预期结果/用例名称 |
| TestCaseRegenerationLoop | 自动重生闭环 + 熔断机制 |

**输出**: 优化后的测试用例集合（含质量评分、优化状态）

#### 阶段6：测试用例导出与评审

**输入**: 优化后的测试用例集合

**处理步骤**:
1. 导出为Excel格式（含质量评分列）
2. 标注 needs_human_review 的用例提交人工复查
3. 生成用例评审报告（含质量分布统计）
4. 输出用例索引文件

**输出**: 测试用例Excel文件、评审报告

## 数据流转路径

```
用户需求 ──► 需求解析器 ──► 知识检索器 ──► 流程分析器 ──► 用例生成器 ──► 输出导出器
                                 │                 │
                                 ▼                 ▼
                            知识库(业务规则)    测试规范(模板)
```

## 关键操作步骤

### 启动测试用例生成

```python
from modules.trae_test.utils.test_case_generator import TestCaseGenerator

generator = TestCaseGenerator()
generator.load_knowledge_base()
cases = generator.generate_cases(requirement_text)
generator.export_to_excel(cases, output_path)
```

### 执行流程

1. **初始化**: 创建 `TestCaseGenerator` 实例
2. **加载知识**: 调用 `load_knowledge_base()` 加载知识库
3. **生成用例**: 调用 `generate_cases()` 传入需求文本
4. **导出结果**: 调用 `export_to_excel()` 导出结果

## 异常处理

| 异常场景 | 处理策略 |
|----------|----------|
| 需求描述模糊 | 提示用户补充信息 |
| 知识库不完整 | 使用默认模板生成，标记需人工审核 |
| 无匹配业务规则 | 生成通用测试用例 |
| 用例数量过多 | 按优先级筛选输出 |

## 输出格式规范

### Excel文件格式

**文件名格式**：`需求{id}{需求名}.xlsx`

示例：
- 有需求ID：`需求1001236销售订单SKU图片显示.xlsx`
- 无需求ID：`需求销售订单导出时间优化.xlsx`

**输出路径**：`workspace/YYYYMMDD/`，日期目录下不再创建 `formal/`、`draft/` 等子目录。

示例：
- `workspace/20260513/需求1001236销售订单SKU图片显示.xlsx`
- `workspace/20260513/需求销售订单导出时间优化.xlsx`

**输出要求**：
- 明确只生成 `.xlsx` 格式的 Excel 文件
- 禁止生成 `.json`、`.md`、`.csv` 等其他格式
- 禁止输出到 `output/`、`test_cases_output/`、`modules/trae_test/output/` 等其他目录

### Excel表头规范

15字段标准顺序（必须严格遵循）：
1. 用例目录
2. 用例名称
3. 需求ID
4. 前置条件
5. 用例步骤
6. 预期结果
7. 用例类型
8. 用例状态
9. 用例等级
10. 创建人
11. 优先级
12. 是否可自动化
13. 关联缺陷ID
14. 回归测试标识
15. 知识库关联

### 评审报告格式
- 用例总数
- 优先级分布
- 覆盖功能点
- 待确认项
