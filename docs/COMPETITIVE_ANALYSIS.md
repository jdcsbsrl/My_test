# ERP 测试自动化竞品分析报告

> 调研日期：2026-07-27  
> 最近更新：2026-07-28  
> 项目：test_erp，Python + pytest + Playwright 的 ERP 测试自动化平台

## 现状修订

自愈功能 V1 已完成并进入 `main`。此前文档中“本项目无自愈能力”“自愈能力缺失”等描述已经不再准确。

当前自愈能力范围：

- 已实现 `SelfHealingLocator`，提供 Playwright 定位级联。
- 已接入 `BasePage.click()`、`fill()`、`wait_for_element()`、`try_click()`、`try_fill()`、`try_click_by_role()`。
- 支持选择器链、role/name、文本、语义属性和 DOM 文本兜底。
- 默认关闭，仅允许在 `test`、`test_env`、`uat` 环境启用。
- 支持 Allure 附件、截图、harness metrics、自愈次数限制和基础熔断。

尚未实现或仍处于 V2 规划：

- 视觉定位兜底。
- 自愈成功策略持久化与人工审核流程。
- 策略权重自动优化。
- 跨模块自愈效果统计看板。

## 竞品能力对比摘要

| 能力维度 | test_erp 当前状态 | Mabl/Testim/Functionize 等竞品 |
|---|---|---|
| 测试用例生成 | 已具备知识库/RAG 驱动基础 | 部分支持 NLP 或 AI 生成 |
| UI 自动化 | Playwright 页面对象 + Facade | 通用 Web UI 自动化 |
| 自愈能力 | V1 已实现，非视觉定位级联 | 多数具备商业化 AI/ML 自愈 |
| 视觉定位 | V2 规划 | 部分竞品已支持 |
| 测试数据生命周期 | 已有数据工厂和生命周期管理 | 多数只支持数据驱动 |
| 代码审核 | 已有 AuditGateway/AuditAgent | 通常不具备 |
| ERP 领域深度 | 销售、库存、导出等模块已有沉淀 | 多数偏通用 Web，ERP 深度有限 |
| 私有化/自主可控 | Python 开源技术栈，可内网部署 | 多数为 SaaS 或商业平台 |

## 差异化优势

1. **ERP 领域知识驱动**

   项目通过本地知识库、检索 API 和用例生成工具沉淀 ERP 业务规则，适合销售订单、库存、导出等业务流程的深度测试。

2. **测试数据生命周期**

   `test_data_factory.py` 和 `test_data_lifecycle.py` 提供测试数据创建、加载、版本管理和清理能力，这是多数通用 UI 自动化平台不覆盖的部分。

3. **审核网关**

   `AuditGateway`、`CodeAuditor`、`SecurityAuditor` 等组件把测试交付前审核纳入工程流程，形成“生成、执行、审核”的质量闭环。

4. **自愈 V1 已补齐核心短板**

   当前 V1 已覆盖常见的选择器失效、文本轻微变化、语义属性可定位等场景。与竞品相比，视觉定位和策略学习仍是后续重点。

## 风险与后续建议

| 优先级 | 建议 | 说明 |
|---|---|---|
| P0 | 持续统计自愈事件 | 通过 `reports/harness_metrics/events.jsonl` 衡量自愈率、耗时和误定位风险 |
| P0 | 扩大销售/库存模块试点 | 优先覆盖高频 UI 变更页面 |
| P1 | 增加人工复核闭环 | 自愈成功后保留截图和 Allure 证据，便于人工确认 |
| P1 | 规划视觉定位 V2 | 仅作为最终 fallback，避免误定位 |
| P2 | 策略持久化与权重优化 | 基于历史成功案例优化策略顺序 |

## 结论

test_erp 现在已经不再是“无自愈”的自动化框架。更准确的定位是：

> test_erp 是面向 ERP 场景的知识库驱动测试自动化平台，已具备用例生成、自动化执行、测试数据生命周期、审核网关和自愈定位 V1 能力；下一阶段应重点强化自愈统计、人工复核、策略学习和视觉兜底。
