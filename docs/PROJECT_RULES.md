# Test ERP 项目规则

> 版本：v2.2
> 生效日期：2026-11-12
> 维护人：Test ERP Team

---

## 一、模块分工与职责

### trae_test 模块
- 负责测试用例生成、测试场景分析、测试数据生成、测试用例模板管理
- 核心工具：`modules/trae_test/utils/` 目录下的各类工具

### auto_test 模块
- 负责测试环境配置、测试脚本执行、测试结果收集与分析
- 核心组件：`modules/auto_test/core/`、`modules/auto_test/drivers/`、`modules/auto_test/pages/`、`modules/auto_test/tests/` 等

---

## 二、环境安全红线

1. **常规环境**：自动化测试仅在 UAT/内网测试环境执行（配置标识 `test`、`uat`）。
2. **生产环境例外**：默认不在生产环境测试；只有用户在当前任务中明确要求时，才可按其指定的环境、数据和操作范围执行。不得从历史授权或历史记录推断本次授权。
3. **入口边界**：正式回归入口 `tools/run_regression.py` 只接受 `test`、`uat`，不支持 `prod`。生产数据专项任务须使用经确认的专用只读流程，不得绕过入口的环境校验。
4. **执行授权与验证**：测试执行必须获得用户对当前任务的明确批准，并验证实际端点属于经批准的环境。`--execute` 只控制程序是否运行，不构成用户授权。
5. **敏感信息保护**：配置文件中的真实密码、API 密钥等绝对禁止提交到 Git。

---

## 三、工作流程

### 测试用例生成流程
1. 检索业务知识库
2. 梳理业务流程
3. 生成测试用例
4. **调用 AuditAgent.audit_test_cases() 审核字段值**
5. **审核通过后**再导出为标准格式
6. 审核**未通过则必须修复后重新审核**，禁止跳过

### 自动化测试执行流程
1. 确认当前任务的执行授权与环境（`test`/`uat`）
2. 配置测试环境
3. 准备测试数据
4. 执行测试脚本
5. 收集测试结果
6. 生成测试报告
